# G04 战斗公式与事件表 V0.2

更新日期：2026-09-25。依据：[伤害数值体系决策表 V0.1](./伤害数值体系待确认决策表V0.1.md)、[P0 决策记录 V0.2](./P0战斗竖切决策记录V0.2.md)、此前逐项确认的伤害主链，以及《小胖地下城战斗系统策划案 V1.3》。本稿替代 G04 V0.1 中的伤害公式与相应事件字段；[G02 V0.2](./G02动作表与敌人招式表V0.2.md)、[G03 V0.2](./G03房间拓扑与遭遇刷怪表V0.2.md)分别负责动作时间和遭遇配置。本稿是**首测配置口径**，数值须经 100 次模拟与 10 次试玩复核。

## 1. 一次命中的伤害主链

```text
武器底材与局部词条得到武器面板
→ 动作系数
→ 技能内转化 / Gain
→ 技能外转化 / Gain
→ 对各伤害分量求适用的 Inc 总和
→ 对各伤害分量逐项相乘适用的 More
→ 本次命中只掷一次暴击；所有分量共享结果
→ 按最终伤害类型分别结算护甲或元素抗性
→ 汇总各分量为一次最终伤害
→ 先扣护盾、再扣生命
→ 记录实际移除量并处理吸血、死亡和派生事件
```

- `Gain` 增加本次命中的伤害分量，不另开一次命中。转化只改变被转出的分量归属；同一来源的转化与 Gain 要保留来源 ID，避免重复计算。`Inc` 只把**适用**增益加总，`More` 逐项相乘；不把 Gain 当作额外行动或再次触发命中事件。
- 暴击在防御之前判定。首测长剑基础暴击率 **5%**、暴击伤害倍率 **150%**。不设置 75% 暴击率或 250% 暴伤倍率的构筑硬上限；概率判定只能在 0～100% 内生效，超出 100% 的暴击率不自动转换为其他属性。暴击成长由词条预算和实测控制。
- 物理分量使用护甲，元素分量使用对应元素抗性；**按最终伤害类型**而非武器/技能名称判定防御。护盾吸收的是**防御后的最终伤害**，不是原始伤害。护盾与生命实际移除量之和不能超过其受击前剩余池；超杀部分不计入吸血。
- 每次主行动与每目标的命中上限仍由 G02 的动作配置和效果来源定义。派生命中默认不能再递归产生同类派生，例外须指定触发上限。

## 2. 护甲、抗性与状态边界

### 2.1 物理伤害

首阶 `K=100`，之后暂随该阶推荐等级的**玩家基础生命**同比增长。目标护甲为 `A`；已生效的破甲比例之和为 `B`，本次攻击适用的护甲穿透比例之和为 `P`：

```text
B = min(各不同来源破甲比例之和, 60%)
P = min(本次适用穿透比例之和, 60%)
A_eff = max(0, A × (1 − B) × (1 − P))
物理减伤率 = min(70%, A_eff / (A_eff + K))
防御后物理伤害 = 防御前物理分量 × (1 − 物理减伤率)
```

同一状态 ID 的破甲重复施加只刷新，不额外叠层；不同 ID 的有效破甲合并后受 60% 上限约束。破甲是目标状态，需在**之前**的命中中生效；当前命中新施加的破甲不回溯增伤当前命中。穿透仅影响本次命中的防御计算，不修改目标状态。首阶基准玩家护甲约 `K/4`（20% 减伤）、基准 Boss 护甲约 `K/3`（25% 减伤）；**首测普通怪 0—5%**、精英 10～20%、Boss 20～30% 物理减伤。

### 2.2 元素伤害

元素抗性按百分点结算，目标原抗性与抗性降低效果合并后，首测范围为 **−50%～75%**。元素穿透合计最多 **40 个百分点**，只对正抗性生效，不能把抗性从正数穿至负数；已是负抗性的目标不再受穿透影响。抗性降低是目标状态，可把抗性降为负数。同 ID 刷新、不同 ID 合并的原则同破甲；新施加的状态从下一次命中起影响伤害。

```text
R = clamp(目标抗性 − 已生效抗性降低, −50%, 75%)
P_e = min(适用元素穿透百分点之和, 40 个百分点)
R_eff = R − min(max(R, 0), P_e)
防御后该元素伤害 = 防御前元素分量 × (1 − R_eff)
```

同阶基准敌人对物理和元素的有效减伤可先以约 20% 为长期预算参考，不要求每只怪一致；**P09 首测普通怪物理减伤为 0—5%**，以 60 HP、72 长剑面板和次目标 90% 系数校准非暴击一挥击杀，不能把普通怪也固定为 20% 减伤。`R_eff` 是本次计算值，不写回目标抗性。

### 2.3 护盾、生命与生命吸取

首测基准角色不自带护盾；护盾仅由明确技能/词条提供，不自动再生。一次命中先按 §2.1/2.2 得到各类型防御后分量，汇总并向上取整一次得到 `D`，再 `shield_removed = min(当前护盾,D)`，`hp_removed = min(当前生命,max(0,D−shield_removed))`。实际伤害是两者之和，不含超杀。默认生命吸取只由**直接命中**触发，按实际盾伤＋血伤计算，立即回复；每秒最多回复自身最大生命的 **10%**，不设单次命中上限，超额不储存。DoT、状态跳伤默认不吸血，除非词条明确改写。

## 3. 持续伤害与受击窗口

- 每种 DoT 是独立实例，不是原命中的第二次伤害。施加时以可用于该状态的对应类型基础伤害建立实例：读取当时来源属性快照，包括适用的通用/DoT 专用 Inc 与 More，但不继承**仅适用于命中**的 Inc/More、暴击和命中防御结果。跳伤时动态读取目标当前防御；首测每 **0.5 秒**跳一次。同一状态默认只保留当时最强一份，细分来源的例外须显式配置。DoT 不触发命中、暴击和普通生命吸取。
- 流血：可用于流血的物理基础伤害 × **25%/秒**，持续 **2 秒**；燃烧：可用于燃烧的火焰基础伤害 × **25%/秒**，持续 **2 秒**。中毒的伤害类型、叠层上限待对应武器设计时确认。
- 玩家承受敌方**命中**时，以 **0.4 秒**为受击窗口：窗口内只承受最高的一笔，后来的更强命中只补差额；DoT 不计入该窗口。窗口包含起始模拟步、不包含终止步；60Hz 试作时长为 24 步。DoT 在施加后经过完整 0.5 秒首次跳伤，60Hz 试作时为第 30 步，之后每 30 步一次；边界同一步按 G04 稳定事件排序执行。不同来源仍须保留命中日志，防止伤害归因丢失。首测敌人单次有效命中以玩家最大生命为参照：普通怪约 3%，精英常规/重招约 9%/16%，Boss 常规/重招约 10%/25%（均指基准防御后）。

## 4. 首测数值与动作接口

| 事项 | 首测口径 |
|---|---|
| 角色与长剑 | 专精 1 级，生命 100，每升 1 级基础生命 +5；升级不给自动攻击/法术威力/移速。首把武器固定保底；长剑面板攻击威力约 72，基础挥斩 0.6 秒、100% 动作系数、纯物理，基础暴击 5%/150%。 |
| 长剑基础范围 | 80° 扇形、距离暂为玩家碰撞体直径的 2.5 倍；最多命中 6 个，目标 2～6 按 90% 动作系数；每主行动基础剑势最多 +1。基础挥斩不降低玩家移动速度。范围构筑的角度成长目标可达约 110～120°，具体节点数值待单独审查。 |
| 基础剑势增伤归属 | P10 已确认每层 +2% 在 5 层内加算，满层 +10% 计入适用的 Inc 池；不另作为独立 More 或两池重复计算。 |
| 自动索敌 | 根据候选扇形的覆盖价值选朝向：普通怪 1、精英 4、Boss 7；同分优先已锁定目标，再取较近目标。 |
| 首阶敌人生命 | 普通 60、精英 400、Boss 1200；参考普通房 18 怪、精英房 1 精英＋12 普通怪。后续固定阶位按同阶基准 DPS 相对 1 级的倍率扩展，不随玩家当前数值实时缩放。 |
| 基准输出与通关 | 同阶对 Boss 有效攻击期间参考 DPS：1 级约 100、首次共鸣阶段约 17 级 200、60 级约 1000。首阶普通房清场 2～3 秒、精英房 4～6 秒、Boss 交战 14～17 秒；典型全程 80 分位低于 60 秒。常规地下城不计时失败。 |
| 移动与路线 | 玩家手动移动，主武器自动攻击；基础移速 4 个玩家碰撞体直径/秒；测试路线非战斗必经路程约 55 个直径。清房后通路自动开放，无开门交互。 |
| 敌方动作 | 同来源杂兵轻击至少间隔 1 秒；精英重招约每 3～4 秒，Boss 重招约每 4～5 秒；重招预警至少 0.7 秒。 |
| 药瓶 | 首个精英房后保底出现 1 瓶；接触后恢复最大生命 30%，不溢出、不带出副本；基准伤害预算不以药瓶为通关前提。 |
| 共鸣 | 首次保底获得的适配共鸣词条，相对同一基准构筑未装备共鸣武器时的**等效战斗收益常规目标不低于 15%**；原 8～12% 目标作废。高于 15% 的目标区间待共鸣专项实测，不设硬上限。共鸣槽内武器不提供基础攻击、普通词条或自动攻击。 |

首测同阶中位武器的总面板强度预算：初期约 **85～90% 底材、10～15% 局部词条**；后期约 **70～75%/25～30%**。这是设计预算，不是随机掉落的强制构成。其余五种武器均须有基础清群方式；同阶标准装备的容差可暂按普通房 2～4 秒、精英房 4～7 秒、Boss 12～18 秒，典型全程仍低于 60 秒。

## 5. 事件合同与复现

保留 G04 V0.1 已定义的 `run_start`、`room_enter`、`room_clear`、`door_open`、`room_transition`、`spawn`、`attack_start`、`action_cancel`、`hit`、`damage`、`status_apply`、`status_expire`、`death`、`run_end` 等事件类型及稳定排序、`parent_event_id` 防递归、同模拟步双死判失败的既有合同；**伤害字段含义按本版覆盖**：

| 字段 | 本版口径 |
|---|---|
| `pre_defense_components` | 按最终类型拆分的暴击后、防御前伤害，含 Gain/Inc/More 来源明细。 |
| `post_defense_value` | 各类型分别过防后汇总的伤害；此值尚未扣盾/扣血。 |
| `shield_removed` / `hp_removed` | 本次实际移除量；生命吸取使用两者之和。 |
| `overkill_value` | `max(0, post_defense_value − shield_removed − hp_removed)`，只用于日志，不用于吸血。 |
| `crit_roll` / `is_critical` | 本次命中唯一暴击判定；DoT 事件无此字段或标明不适用。 |
| `config_version` / `seed` / `action_id` / `parent_event_id` | 版本与种子复现、动作归因、派生上限检查；玩家移动输入按模拟步记录。 |

旧稿 `raw_value/final_value/absorbed_value` 的定义与新顺序冲突，不得直接沿用；如程序已有这些字段，应在迁移表中明确对应并升级事件 schema 版本。**P11 已确认：多类型分量分别过防后汇总，总伤害只向上取整一次，再按护盾→生命扣除**；不能每分量或每阶段提前取整。暂停、倍速和特效丢帧不得改变战斗模拟与事件结果。随机伤害波动首测关闭，但暴击、出生位置/时序等随机源必须由种子驱动。

G03 V0.2 新增的精英房保底药瓶须产生 `potion_spawn`、`potion_pickup`、`heal` 事件，记录药瓶 ID、来源房间、接触玩家、拾取前后 HP、实际恢复量和被最大生命截断的溢出量；事件仍携带 `config_version`、`seed` 与稳定序号，重复拾取不得再次治疗。

P07 的直线投射物与精英/Boss 位移不得穿墙。投射物撞墙销毁时记 `projectile_wall_hit`（`projectile_id`、墙体 ID、命中坐标、模拟步），不再生成该弹道的后续伤害事件；同一步同时可能触及单位和墙体时按稳定碰撞顺序决议并记录。

## 6. 可复算基准与验收

以首阶长剑面板 72、动作系数 100%、无其他修正、无破甲/穿透、Boss 护甲约 `100/3` 为例：非暴击物理命中防御前为 72，Boss 物理减伤约 25%，防御后约 54；若暴击则防御前为 108，防御后约 81。0.6 秒挥斩、5% 暴击带来的**持续站桩期望 DPS**约为 `[(54×0.95)+(81×0.05)]/0.6 = 92.25`，接近 F01 的“约 100”参考值；移动、目标丢失、剑势叠加与后续装备词条会改变实际观测。此例不用于承诺 Boss 1200 生命必然精确 14～17 秒击杀。

验收固定参考装备和可复现种子，至少 **100 次模拟＋10 次人工试玩**，记录 Boss 交战中位数 14～17 秒、普通房 2～3 秒、精英房 4～6 秒、典型全程 80 分位低于 60 秒，并核对房间玩家失血预算（普通 5～8% 最大生命、精英 10～15%、Boss 25～35%）。P13 计时口径：普通/精英房为 `room_enter→room_clear`；Boss 有效交战为任一方首次合法发起攻击→Boss 死亡；整局为 RM01 首次可操作移动→唯一胜败结算，暂停/加载不计，移动与战斗重叠只计一次。模拟验证数值分布，试玩验证移动、索敌、预警和清群手感。攻击/法术、Gain/Inc/More、DoT、护盾、吸血、破甲与穿透各需至少一个无随机可复算单测。

## 7. 专项后续与边界验证

- 首把适配共鸣武器的**最低目标为 15%**；更高收益的合理波动区间、防御／清群收益的等价量化方式和极端组合控制，待共鸣设计/实测；此处没有再设上限。
- 中毒类型和叠层、护盾来源与显示、长剑小节点的具体加成数字，留给对应内容表；不以本版公式稿擅自替换。
- 长剑 R00 剑势的 +10% 满层结果已由 P10 确认为适用的 Inc，不能再按历史稿同时处理为独立 More；后续节点引入独立 More 时必须有独立来源 ID。
- P11 的单次向上取整、0.5 秒 DoT 首跳和 0.4 秒窗口边界已确认；正式实现仍须用边界单测复核整数/小数、同一步事件和 60Hz 试作步数，不把规则确认等同于代码测试通过。
