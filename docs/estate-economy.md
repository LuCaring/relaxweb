# 休闲庄园经济基线 v1

2026-09-19 完成首轮数值审阅。权威配置为 `estate/catalog.py`，公开目录版本为 `v1`。
所有售价固定，不设每日收益上限；金额均为现有账号的游戏金币。

## 农场

初始 4 块土地，最多 8 块。购买种子后等待成熟，无需浇水，离线继续计时；成熟后不枯萎。
小麦保留 20 金币种子、30 金币售价、5 分钟成熟，新手每轮 4 块地投入 80、回收 120。
普通一级地单块每小时理论净收益约 96–120 金币；2–8 级作物逐步提高到约
120、135、150、165、180、195、210 金币。这里的小时收益假设成熟立即补种，
未扣土地购置成本；实际离线收益取决于收获频率。

长周期作物提供更高的单次收益和经验，适合离线等待，不再被小麦长期压制。
神奇草需 6 级、24 小时；奇迹花需 7 级、36 小时；星露果需 8 级、48 小时。
土地升级后等待变为原来的 85% / 65%，只影响之后播种的作物。
新增土地价格依次 500 / 900 / 1600 / 2600；单地升级 500 / 1500。
仓库容量 100 / 200 / 350，扩容价格 1000 / 3000。升级节奏同时受到等级与本金限制。

## 钓鱼

每轮消耗一份鱼饵与一点鱼竿耐久，断线、逃脱和放弃也消耗。
基础鱼竿购置 300；升级 900 / 2400；每轮维修分摊约 4.50 / 6.29 / 8.73。
蚯蚓 15 金币，荧光虫饵调整为 25 金币。鱼饵和鱼竿会限制可遇到的最高稀有度，
并影响稀有鱼权重；不改变收购价。收藏物只进入收藏库存，不出售。

各档每种鱼基础权重为 100 / 22 / 4 / 0.6 / 0.08 / 0.006，再应用装备与鱼饵加成。
普通鱼承担日常收益，神秘鱼等传奇鱼保持罕见。
固定随机种子，每套配置模拟 20,000 次抽取，将收藏物按零售价计入：

- 基础竿配蚯蚓：全成功时平均净收益约 56.30 / 轮。
- 中级竿配荧光虫饵：约 78.88 / 轮。
- 顶级竿配荧光虫饵：约 91.14 / 轮；两种传奇鱼合计抽中率约 0.175%。
- 假设所有种类统一为 70% 捕获率，上述三档平均净收益约 33.56 / 45.83 / 53.68。

这些是扣鱼饵和维修分摊、未扣购置升级费用的模拟均值，不保证单轮收益，
也不是实测玩家成功率。困难鱼实际更容易失败，收藏品实际获得还需完成收线。

## 矿场

矿镐购置 350，升级 1100 / 2800。每轮消耗一点耐久，三级维修分摊为 10 / 15 / 20。
矿物售价为石料 5、煤块 10、铜矿 20、铁矿 38、紫晶 85、星辉宝石 200。
每份矿物经验依次为 2 / 3 / 4 / 6 / 10 / 16，结束时统一发放，重复结算不重复加经验。

25 格中固定 2 个加镐格，浅 / 中 / 深层分别有 1 / 2 / 3 个炸弹，初始可敲 8 / 11 / 14 次。
每层使用对应等级矿镐，不提前退出，按固定顺序模拟 20,000 块隐藏棋盘：

- 浅层平均净收益 64.04 / 轮，触雷约 38.0%，净亏损约 7.9%。
- 中层平均净收益 94.68 / 轮，触雷约 78.4%，净亏损约 16.8%。
- 深层平均净收益 110.85 / 轮，触雷约 97.0%，净亏损约 22.8%。

触雷停止本轮但保留已挖矿物，因此触雷率不等于亏损率；深层的主要风险是
提前失去剩余敲击机会。玩家可随时带走收获。模拟不窥视矿格，也未将点击速度
换算为小时收益，不代表挂机收益保证。

## 存档与上线

不清空已有金币、等级、仓库、工具、土地或正在生长的作物；已种下作物的
成熟时间不变。出售和收获使用当前目录，因此旧库存售价与未收获作物经验
也会随本次数值调整。已完成活动的重放结果保持原结算。

启动服务时幂等增加矿场 `reserved_slots` 字段，旧矿局保持原 12 格预留。
新矿局按最大产出预留 10 / 13 / 16 格，结算释放对应预留；老矿局若需要
额外仓位则要求玩家先出售库存。钓鱼消耗鱼饵腾出位置，满仓也可使用现有鱼饵。
更新前备份数据库，部署后重启聊天服务并刷新游戏页。

## 复核

运行 `python tests/test_estate_economy.py` 可重现 100,000 次鱼获抽样与 60,000 次矿局模拟。
`python -m unittest discover -s tests -p 'test_estate_*.py'` 检查领域逻辑、迁移和经济边界。
另外独立运行 `python tests/test_estate_protocol.py` 与
`python tests/test_estate_activities_protocol.py` 验证真实 WebSocket 事务闭环。
后续可根据玩家实际成功率和在线频率调整 v1，但不能把模拟均值当作保底收入。
